# SuperCar2 模块简化重构规划

日期：2026-10-05。状态：已于 2026-10-05 实施完成，本文保留原规划与旧文件映射作为历史记录。实施交接见 [项目交接文档](项目交接文档.md)。

当前协议范围已按用户后续要求收拢为 Emm 专用版本，下面模块职责与映射已同步。

## 1. 调整目标

用户希望按“串口一类、电机驱动一类”组织程序，减少当前按传输、CRC、协议、解析器、状态机等细节拆分的文件。保留模块化编程，以 3 组业务源文件替代当前 10 个应用源文件；CubeMX 生成文件不计入这 3 组。

本次后续重构以整理结构、改善阅读为目标，沿用现有引脚、协议、参数和控制行为。ROS、导航和里程计仍由香橙派负责。

## 2. 建议文件布局

```text
SuperCar2/
├─ Core/Inc/
│  ├─ car_uart.h       串口通信对外接口
│  ├─ car_motor.h      电机控制接口、结果和反馈类型
│  ├─ car_control.h    整车入口、故障和保活接口
│  ├─ car_config.h     集中配置
│  └─ ...             CubeMX 原有头文件
├─ Core/Src/
│  ├─ car_uart.c       两路 UART 收发、上位机协议与反馈
│  ├─ car_motor.c      X42S 帧、回包、共享总线与双轮状态
│  ├─ car_control.c    调度、急停、断联保护、故障恢复配合、LED/IWDG
│  ├─ main.c          CubeMX 初始化、调用整车入口
│  └─ ...             CubeMX 原有中断、MSP、系统文件
├─ docs/              唯一项目文档目录
├─ tools/             编译、测试、上位机参考工具
└─ tests/             软件回归测试
```

| 模块 | 包含的工作 | 内部组织方式 |
| --- | --- | --- |
| `car_uart` 串口通信 | USART1/2 中断收发、缓冲、发送队列、错误恢复；上位机 ASCII/二进制协议、CRC、序号检查、ACK 与遥测 | 文件内分为“底层收发”“上位机解码”“命令处理”“反馈发送”几段 |
| `car_motor` 电机驱动 | Emm 帧构造、驱动器回包解析；配置检查、共享总线事务、双轮速度/位置、停止和解除保护 | 文件内分为“协议帧”“回包”“总线调度”“电机控制接口”几段 |
| `car_control` 整车控制与保护 | 初始化、主循环调度；急停/可选故障输入、保活超时、故障锁存；LED、看门狗 | 文件内分为“板级 IO”“保护逻辑”“整车入口”几段 |
| `car_config.h` 配置 | 地址、方向、限速、周期、保护开关、缓冲容量 | 保持唯一默认参数入口 |

回包解析属于电机驱动，上位机报文解析属于串口通信；两者都在主循环执行。串口中断只维护收发，不执行控制命令。

## 4. 调用关系和接口原则

`main.c` 建议改为在 USER CODE 区调用：

```c
CarControl_Init(&huart1, &huart2);
/* while (1) 中 */
CarControl_Poll();
```

`car_control` 调度串口维护、上位机命令处理、电机轮询和遥测。`car_uart` 将有效命令交给电机/整车接口；`car_motor` 通过串口模块发送电机帧、取接收字节，并向整车模块报告故障。

串口维护与上位机命令处理保留不同的内部调用入口，以维持“安全检查→处理命令→再次安全检查”的顺序。不能因为合并文件而把全部工作挪到一个串口调用中。

头文件只公开跨模块实际需要的接口与类型：串口收发及协议处理、电机使能/速度/位置/停止/反馈、整车故障/保活/调度。帧拼接、CRC、解析器状态和队列下标尽量留在 `.c` 内；统一使用清晰的函数前缀，避免合并后的静态函数/变量重名。不需要为此次整理引入消息总线、注册机制或通用框架。

可沿用已有清楚的函数名，入口推荐使用 `CarControl_*`；统一前缀时须同步测试和文档。无需为了改文件布局重写状态机。

## 5. 原实施顺序（已完成）

1. 先运行当前构建和测试，记录基线，保留工作副本或补丁。
2. 合并串口模块，处理同名静态符号、头文件引用和唯一 HAL UART 回调；保持协议字节不变。
3. 合并电机模块，保留事务超时、停止抢占、反馈状态和位置只发送一次的行为。
4. 合并整车模块，保留调度顺序及保护条件；更新 `main.c` 的 USER CODE 调用。
5. 调整模拟 HAL 和测试入口，删除旧应用文件，重新注册 Keil 源文件，执行 ARM 构建和软件回归。
6. 更新 README、实施/联调文档及离线 HTML 模块说明和内嵌文档，交付最终文件列表、验证结果与待实车项目。

合并期间可分步验证；最终应用目录只保留上述 3 个业务 `.c` 和对应头文件、配置头文件。不要重新拆出 CRC、parser、transport、manager 等小文件。

## 6. 验收标准

- 查串口功能主要看 `car_uart`，查电机功能主要看 `car_motor`，查整体运行和保护主要看 `car_control`；每个文件有清楚的段落说明。
- `main.c` 保持简短，CubeMX USER CODE 区之外不混入业务逻辑；驱动和控制路径不新增运行期阻塞等待、动态内存。
- 线上的 ASCII/二进制协议、故障位、方向和单位与当前文档一致。
- 启动失能、配置门禁、急停、300 ms 保活、异步清故障、共享总线、TX 缓冲生命周期和位置去重回归全部保留。
- ARM 编译/链接和软件模拟测试通过，无重复 HAL 回调或旧源文件残留；文档明确实际测试范围。

更细的现状、关键约束、测试适配问题和可直接复制的接手指令见 [项目交接文档](项目交接文档.md)。

## 7. 实施结果（2026-10-05）

最终业务文件为 `car_uart.c/.h`、`car_motor.c/.h`、`car_control.c/.h` 和 `car_config.h`，生产入口使用 `CarUart_*`、`CarMotor_*`、`CarControl_*`。main 仅接入整车初始化和循环。板级、安全和整车调度已合入 car_control，模拟测试编译真实板级实现，旧替身与排除项已清理。

ARM5 实际编译/链接通过，无告警或错误；完整现有固件回归、板级 GPIO/LED/IWDG 寄存器新增验证和 3 项 Python 协议测试通过。ROM 13492 字节、RW/ZI 3376 字节。文档、Keil 分组及离线 HTML 内嵌 Markdown 已同步。仍需烧录并完成实际电机、电气连接、方向和看门狗硬件时序验收。
