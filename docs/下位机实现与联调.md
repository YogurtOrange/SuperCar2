# SuperCar2 下位机实现与联调

## 1. 采用的设计

以工作空间较新的《X42S上位机-STM32电机控制实施方案_v1》及接线 HTML 为基础，沿用旧 SuperCar 的周期调度/状态分层思想，底层改为 X42S 串口控制。本工程不使用旧直流电机 PWM、编码器、循迹、IMU PID 输出。ROS、Mid-360 和路径规划属于香橙派。

工作空间原 `docs` 已迁入本工程并删除。X42S 方案、ROS 方案、接线 HTML 和内嵌资料均按当前工程更新，统一为 USART1 电机、USART2 上位机及相同的二进制 TYPE 编号。文档入口见 [文档索引](README.md)，通信细节以 `上位机协议_v1.md`、默认参数以配置头文件为准。

协议核对依据为用户提供的《ZDT_X42S第二代闭环步进电机用户手册 V1.0.5_260527》：第 40 页 ACK，第 50/53/57/60 页运动，第 71–74 页反馈，第 77 页选项，第 103–105 页 Emm 配置。保留本地 Emm_V5 参考代码的帧布局，修正其旧版位置模式只有 bool 的限制。

## 2. 接线及 CubeMX

| STM32 | 用途 | 配置 |
| --- | --- | --- |
| PA9 / PA10 | USART1 电机总线 TX / RX，地址 01/02 | 115200 / 8N1，RX/TX 中断 |
| PA2 / PA3 | USART2 香橙派/CH343 TX / RX | 115200 / 8N1，RX/TX 中断 |
| PB12 | 急停开关接 GND，低有效 | 输入上拉，软件每轮扫描，默认启用 |
| PB13 / PB14 | 可选左右故障输入，低有效 | 输入上拉，默认不参与保护 |
| PC13 | 常见开发板状态 LED | 推挽低速，低有效；无故障约 500 ms 翻转，故障约 100 ms |
| PA13 / PA14 | SWD | 保留 |
| PD0 / PD1 | HSE | 原工程 8 MHz，PLL×9=72 MHz |

PB12/13/14、PC13 在 `.ioc` 中补齐，`car_control.c` 同时保留模块初始化，保证重新生成代码也能运行。USART1/2 IRQ 仍调用 HAL，全部 HAL UART 回调统一位于 `car_uart.c`。不要在其他模块再定义同名 HAL 回调。

当前香橙派 26 Pin UART0：物理 8 脚 TX→PA3，物理 10 脚 RX←PA2，物理 14 脚 GND 共地，使用 `orangepi_host_test.py` 的默认 `/dev/ttyS0`。也可启用 UART1，改用物理 5 脚 TX、3 脚 RX 和 `/dev/ttyS1`。CH343 是替代上位机入口，两者 TX 不同时接到 PA3。STM32 PA9→两驱动器 R/A/H，PA10←T/B/L；共享接法限于厂商支持多机总线的 TTL 板卡。RS485/CAN 版本需要对应收发器和适配，本工程当前没有 DE/RE、CAN 驱动。图文接线可查看 `共享串口接线与CubeMX配置总览.html`。

## 3. 电机参数和可调项

详细参数表、修改后的编译/烧录步骤、单轮/双轮调速及加速度对比方法见 [参数说明与调参指南](参数说明与调参指南.md)。`car_config.h` 和三个模块的接口/关键路径已添加中文注释，常规调参先看配置头文件和该指南。

上电前分别设置左右驱动器地址 01 / 02，Emm 固件，UART，115200，固定 6B 校验，Response=Receive，关闭定时主动回传、上电自动运行/自动回零，关闭缩小 10 倍输入功能。先完成空载校准。

初始化每轮读取 1A、42、3A、35，随后发送失能。要求 42 配置回包 33 字节/21 参数，UART、波特率 115200、正确地址、固定 6B、Receive，应答选项为 Emm 且无缩放。配置内容不匹配时锁存配置故障，不自动修改驱动器永久参数。配置帧只接受 Emm 的 33 字节长度，非法长度按错误帧丢弃；没有有效匹配应答时按事务超时处理。

2026-10-09实测修正：X42S_V1.0/Emm的1A选项回包为5字节 `Addr 1A option_hi option_lo 6B`。右轮实测 `02 1A 00 06 6B`，选项为大端uint16 `0x0006`。此前固件与模拟驱动器错误地使用4字节，导致正常1A回包被丢弃并锁存FAULT_MOTOR_COMM；现已同步修正长度、字段宽度和诊断程序，并把用户实测1A/42回包纳入回归。保护门禁保留，收到合法回包后才继续初始化。

`Core/Inc/car_config.h` 是集中配置入口：

- `CAR_LEFT_ADDR / CAR_RIGHT_ADDR`：当前实际接线默认为 01/02（左/右），必须不同；旧巡线工程的相反映射不沿用。
- `CAR_LEFT_SIGN / CAR_RIGHT_SIGN`：默认 +1/-1，对镜像安装的方向假设；必须低速实测。
- `CAR_MAX_RPM`：初始 60，超范围拒绝。手册 Emm 驱动器最大 3000 RPM，车体允许速度须负载标定后确定。
- `CAR_SINGLE_MOTOR_TEST`：0=双轮，1=只接左轮，2=只接右轮；只调度所选轮，不需要插不存在的电机。当前双轮设为0，重新编译烧录后Python不加单轮参数，两台驱动器均须连接并上电。
- `CAR_USE_ESTOP_PIN`：默认 1，PB12 输入上拉，悬空表示释放。
- `CAR_USE_FAULT_PINS`：默认 0；确认确有独立报警输出及有效电平再启用 PB13/14。共享 UART 的 T/B/L 已用于回包，不能同时当报警线接入。
- `CAR_USE_IWDG`：默认 1，标称约 1 s，调试器暂停时冻结，主循环喂狗。没有添加轮径/轮距假值。

## 4. 调度、状态和停止

主循环不断调用 `CarControl_Poll`：先传输维护，再安全检查、解析上位机命令、再次检查安全、处理电机、反馈和喂狗。无运行期 HAL_Delay 或阻塞发送，无动态内存。ISR 只搬字节和启动下一字节接收；协议及状态机在主循环运行。

共享总线每次只有一个等待应答的事务。正常命令等待指定地址和功能码的回包，再发下一条；20 ms 无回应则锁存电机通信故障，并给总线留 25 ms 安静时间。电机每帧发送完成后至少留 5 ms 间隔，沿用已验证巡线代码但由时间戳非阻塞实现。RX 逐字节中断加 256 字节环形队列，TX 用 HAL_UART_Transmit_IT；上位机 TX 有 8 槽缓冲（实际预留空间管理），满时丢报告，不阻塞控制。TX 超过 20 ms 卡住则终止发送并锁存串口故障。

控制目标随到随更新；相同速度目标 50 ms 刷新，状态/速度每轮约 50 ms 查询，位置约 100 ms 查询。通信延迟或总线压力会影响这些实际周期，反馈时间戳用于检查；运动期间超过 250 ms 无新鲜状态/速度即停机。双轮运动不使用广播同步，接受毫秒级逐台起动差，避免同步等待/回包复杂度。

状态为 INIT→DISABLED→READY→SPEED/POSITION。上电先对两个地址发送停止，再读取参数并失能；无自动使能/运动。使能和运动命令都要电机配置确认且在线，运动还要使能确认。

正常 STOP 清目标、停止双轮，保留当前使能锁轴，STOPPING 通过新鲜零速度反馈转 READY/DISABLED。保留使能请求期间，即使零速或已 STOP，仍需维持心跳，或明确发送失能请求。位置命令仅发一次，不因更新周期重发，利用随后 3A 到位标志确认结束。运行中继续发另一种运动命令可按驱动器能力切换；待位置命令 ACK 时拒绝新位置请求。

故障锁存后停止优先级最高，取消在途事务等待和待执行运动；已开始的 UART 帧会先发完，再发送左右 FE 98，不等待第一个停止 ACK 才停止另一轮。停止 ACK 被忽略，随后查询速度确认；异常未停或反馈不新鲜则每 100 ms 重发停止。300 ms 超时是软件检测阈值，加上主循环和两个短 UART 帧的传输时间才能作用到驱动器。

PB12 低、ESTOP、驱动器堵转、串口错误、电机事务超时、配置异常、上位机断联都会锁存。任何新速度指令和心跳都不会自动清故障。`CLEAR_FAULT` 是异步请求：输入释放→停止→发送 0E 52 解除保护→失能→确认在线/配置/零速/无保护→清锁存。收到 `OK RECOVERY` 后查询 faults=0，再重新使能及下发目标。故障源仍在或恢复事务失败时继续锁定。

独立看门狗在主循环卡住后复位，重启再次走停止/失能。CPU 卡死到复位前无法发送停止；需要硬件急停时，应同时切断驱动器动力/硬件使能。串口线断开时也只能尽力发停止，物理停止需独立硬件路径或驱动器自身保护。驱动器上电自动运行须提前关闭。

## 5. 单轮桌面联调

1. 电机空载，单接地址 01，将单轮开关设 1，重新编译下载。
2. 用 USART2 串口工具 115200 / 8N1，先 `PING`，再 `STATUS`，确认 CONFIG=1、ONLINE=1、FAULT=0。
3. `MOTOR ENABLE 1`，等待约 50 ms，再查询 FLAGS bit0=1。
4. `MOTOR VEL 1 30 10`，每 100 ms `HEARTBEAT`。确认实际正向，STATUS RPM 符号一致。
5. `STOP`，确认新鲜反馈 RPM=0。反向测试 `MOTOR VEL 1 -30 10`。
6. 单次 `MOTOR POS 1 3200 30 10`，持续心跳，确认在 16 细分、1.8° 电机时是一圈；结束查询到位位。不要用连续重复位置命令代替心跳。
7. 停止后故意撤掉心跳；约 300 ms 锁存故障。发送速度应拒绝，CLEAR_FAULT→故障 0→重新使能后再动。
8. PB12 接地，验证急停；保持接地时恢复被拒绝，释放后恢复。

## 6. 双轮与 ROS 接入

改回双轮模式，分别设地址，确认共享总线没有重复应答。分别低速测试方向，修改 sign 后重新编译。两轮使能后 `WHEELS 30 30 10` 应车体前进；`WHEELS -30 30 10` 可做低速原地转向。

上位机订阅 cmd_vel，按照实测轮距、轮径换算左右 RPM，使用 `上位机协议_v1.md` 的二进制消息。反馈 81 使用真实位置计数和各自采样时刻，香橙派处理 odom/TF；初次位置只建立基线，重启后重新建基线，禁止把上电绝对计数直接当成本次移动距离。

必须上板完成：拔上位机线、单驱动器失联、驱动器报警、硬件急停、配置不符、复位、前后转向、位置到位、重复位置帧、负载起停。软件测试无法证明真实电机能停、TTL 多机电气兼容和机械方向。

## 7. 已完成的软件验证

ARM Compiler 5 真实编译/链接使用本工程 `.uvprojx` 中的全部源文件、原 startup 和 HAL，输出 hex/axf/map，无编译告警或错误。Native GCC 仿真测试使用真实 car_uart、car_motor、car_control 三个模块，包括 GPIO/LED/IWDG 板级逻辑，模拟两个驱动器，覆盖：

- Emm 帧向量、CRC16、6B 出现在 payload、噪声/坏 CRC/半帧恢复；
- 上电不运动、配置不符拒绝使能、镜像方向反馈；
- 上位机 300 ms 超时，PING/重复帧不续期，清故障不自动运动；
- 一批命令中急停取消运动目标、物理急停恢复条件；
- 驱动器保护、失联、RX 错误/溢出、TX 卡住；
- 位置只发送一次、ACK 丢失不重发、参数/长度越界拒绝；
- 二进制序号回绕/去重、重连 HELLO 失能；
- 上位机队列高负载时，HAL 正在发送的缓冲不被覆盖。

运行方法见 README。测试源、构建脚本均在工程内，便于后续改动后重复验证。
