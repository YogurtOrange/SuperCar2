接线与硬件分线

香橙派 5 使用排针 UART1 直连 STM32 USART2；STM32 USART1 连接两台 X42S / Emm 电机，电机地址分别为 01 和 02。CH343 可用于调试，当前控制链路使用硬件串口。

CubeMX 逐项设置

  1. 在 MCU Selector 选择 STM32F103C8Tx，封装 LQFP48。
  2. System Core → SYS → Debug：Serial Wire。自动保留 PA13、PA14。
  3. Connectivity → USART1 → Mode：Asynchronous，Hardware Flow Control：Disable。确认 PA9/PA10，没有启用重映射。
  4. Connectivity → USART2 → Mode：Asynchronous，Hardware Flow Control：Disable。确认 PA2/PA3，没有启用重映射。
  5. 两路 Parameter Settings：115200、8 Bits、Parity None、1 Stop Bit、Receive and Transmit、16 Samples。版本不同可能将流控显示为 None。
  6. GPIO Settings：TX 为 Alternate Function Push Pull / High，RX 为 Input mode / No pull-up and no pull-down，详见下表。
  7. NVIC：优先级分组 NVIC_PRIORITYGROUP_4，启用 USART1/USART2 global interrupt，两路抢占优先级 1、子优先级 0。这是本方案建议，两个 IRQ 同级；软件中保持 ISR 简短。
  8. DMA Settings 暂不添加请求。USART3、CAN、PWM、定时器编码器、外部中断暂不启用。
  9. RCC 使用下述 HSE 8 MHz → 72 MHz 设置；PD0/PD1 为晶振功能，图中标绿。工程要求实际开发板有 8 MHz 外部晶振。
  10. SYS Timebase Source 使用 SysTick；SysTick 抢占优先级 15，子优先级 0，HAL 默认提供 1 ms 计时。无需另启 TIM2/3/4。
  11. PB12、PB13、PB14 设 GPIO_Input，上拉；标签 ESTOP_IN、DRIVER_FAULT_L、DRIVER_FAULT_R。PC13 设 GPIO_Output，推挽 Low，初始高，标签 STATUS_LED。
  12. 保持逐字节中断 RX 与非阻塞 TX。独立看门狗由 car_control.c 启动，不需要 CubeMX 另生成重复 IWDG 初始化。重新生成后运行 tools/update_keil_project.py 恢复应用分组。

STM32F1 的 GPIO 配置方式与部分新系列不同，不需要选 AF7。UART RX 使用输入模式；TX 使用复用推挽。HAL 对照：TX 为 GPIO_MODE_AF_PP、GPIO_SPEED_FREQ_HIGH；RX 为 GPIO_MODE_INPUT、GPIO_NOPULL。50 MHz 是输出驱动速度等级，不是串口波特率。部分 CubeMX 版本在输出模式下不显示 Pull 或 RX 下不显示 Speed，保持默认即可。

USART1 的电机共享总线使用 TX 和 RX 两条信号网络，CubeMX 选择 Asynchronous；不要选 Single Wire / Half-Duplex。电机地址和通信协议在软件及驱动器中设置，不在 CubeMX 中设置。

新增 GPIO 已写入 SuperCar2.ioc；CarControl_Init 在应用初始化时实际配置。PB12 每轮主循环扫描，不使用 EXTI；PB13/14 仅在 CAR_USE_FAULT_PINS=1 时参与保护。

时钟、中断与定时

当前时钟：HSE 8 MHz → 72 MHz

  • System Core → RCC → High Speed Clock：Crystal/Ceramic Resonator。只有外部有源时钟输入才选 Bypass Clock Source。
  • Clock Configuration：HSE 输入 8 MHz；PLL Source = HSE；HSE Predivider /1；PLL multiplier ×9；System Clock Mux = PLLCLK。
  • AHB /1，APB1 /2，APB2 /1；SYSCLK/HCLK=72 MHz，PCLK1=36 MHz，PCLK2=72 MHz。USART1 使用 PCLK2；USART2 使用 PCLK1。
  • PD0（5 脚）自动变为 RCC_OSC_IN，PD1（6 脚）自动变为 RCC_OSC_OUT；它们是晶振专用功能，不手动配置为 GPIO 推挽。LSE 仍 Disable。
  • 如果板载晶振频率不是 8 MHz，按实际频率重算 PLL；自制板需要晶振及匹配负载电容。

是否需要开启定时器

当前目标是上位机控制 STM32，再由串口发送 Emm 命令使两台 X42S 转动。电机驱动器负责产生电机驱动脉冲及闭环控制，STM32 无需启用 PWM 或脉冲定时器。TIM2、TIM3、TIM4 保持关闭。

现有 HAL 默认通过 SysTick 每 1 ms 更新计时，可在主循环用 HAL_GetTick() 判断发送周期、回包超时、心跳失联时间。计时建议使用无符号差值 (uint32_t)(HAL_GetTick() - last_tick) >= interval_ms，并保持主循环非阻塞。当前工程已实现非阻塞调度、协议和保护：速度/状态约 50 ms，位置/遥测约 100 ms；20 ms 电机事务超时、250 ms 运动反馈过期、300 ms 上位机保活阈值。

串口优先级为 1、SysTick 为 15，串口中断处理期间 SysTick 无法抢占它。ISR 内不要使用 HAL_Delay() 或等待回包；中断只收字节、记录事件，在主循环处理协议和超时。

后续若需要硬件脉冲输出、输入捕获或对精确周期及抖动有要求，再添加对应 TIM。当前无需为毫秒级通信计时额外开启定时器。

独立看门狗由 CarControl_Init 启动，标称约 1 s，主循环喂狗，调试暂停时冻结。停止检测到实际动作还需要主循环和 UART 短帧传输时间；软件计时不是硬件断电路径。

07

电机设置与供电

  • 转接板上设置三个独立网络：STM32_TX、STM32_RX、GND。每个网络各引出到两个电机；圆点表示连接，拱桥表示跨线不连接。
  • 电机端严格采用 X42S 手册第 26 页支持的 TTL 多机连接；不是通用推挽 UART 输出并联方案。RS485/CAN 版本不能直接照此接线。
  • 左电机地址 01、右电机地址 02。先分别单独连接并设置地址，再并入共享总线。
  • 保持自由协议固定校验 6B、115200，关闭定时主动上报，逐台收发和读取反馈。正常事务等待指定地址/功能码回包后再发下一条；超时锁存故障。
  • 当前逐台立即执行：速度/位置使用 snF=0，接受毫秒级起动差，不发送广播同步启动。停止会取消等待并先把两台停止帧发出，再查询零速。
  • Emm Scale 必须 Disable，当前速度单位为整数 RPM；初始化会拒绝输入缩放配置。默认限速 ±60 RPM，加速度档位 10。
  • 香橙派使用合规 5 V USB-C 电源；STM32 开发板按自身供电接口供电。两块板通信只连 TX、RX、GND，不需要把各自电源正极连接在一起。
  • X42S 常规版按实际版本使用 12/24 V 电源接 V+，负极接 GND，两台驱动共享电源时按总负载选择电源和线径。电机电源正极不接香橙派/STM32 信号或 3.3 V 引脚。
  • 如果是自制 STM32 裸芯片板，VDD/VDDA 接 3.3 V，VSS/VSSA 接地，BOOT0 拉低；还需完整复位、去耦及 VBAT 连接设计，本图不代替最小系统原理图。
  • 本图中电机 COM/EN/STP/DIR 不接；确认电机配置使用 UART 通信及串口使能控制。没有独立报警脚的情况下，通过 3A 状态查询读取故障，不把 UART 返回脚同时用作报警输出。

初始化先发送停止，逐轮读取 1A、42、3A、35，再失能并等待 ACK；配置、在线和初始化确认后才允许使能，实际使能后才接受运动。42 要求 Emm 33 字节/21 参数、UART、115200、正确地址、6B 和 Response=Receive。

位置命令是细分脉冲数，1.8°/16 细分为 3200 脉冲/圈；位置反馈是 65536 ticks/电机圈。默认位置 mode=2，相对当前实时位置。位置只下发一次，随后用心跳保活和 3A 到位标志判断结束。

香橙派串口设置

以手册 Ubuntu/Debian 镜像为例，在 /boot/orangepiEnv.txt 的已有 overlays 中追加 uart1-m1 后重启。Orange Pi OS Arch 镜像使用 /boot/extlinux/extlinux.conf 的 FDTOVERLAYS；以实际安装镜像为准，不覆盖已有配置。

核对 /dev/ttyS1、串口权限、引脚复用及 console/getty 占用；UART1 所在物理 3/5 脚不能同时启用 I2C5。先对香橙派 UART 做回环测试，再连接 STM32。

09

已实现固件与联调

main.c 只接入 CarControl_Init 和 CarControl_Poll。IRQ 调用 HAL；UART RX/TX/错误回调统一在 car_uart.c，中断只搬字节，协议及保护在主循环执行。

模块实际职责
car_uart.c/.h两路 UART 收发、256 字节 RX 环形缓冲、非阻塞 TX、错误恢复；上位机 ASCII/二进制协议、CRC、序号与反馈
car_motor.c/.hEmm 帧/回包、配置门禁、双轮状态、共享总线事务、优先停止与异步恢复
car_control.c/.h协作调度、GPIO、300 ms 保活、急停与故障锁存、LED、独立看门狗
car_config.h地址、方向、限速、周期、缓冲和保护开关的集中配置

正式协议与周期

AA 55 01 TYPE LEN SEQ PAYLOAD CRC_LO CRC_HI；CRC16/MODBUS 覆盖 VER 至 PAYLOAD，payload 小端。01 速度、02 位置、03 STOP、04 ESTOP、05 使能、06 恢复、10 心跳、11 查询、12 HELLO；80 状态、81 反馈、82 故障变化、83 接受应答。

速度/状态约 50 ms，位置/遥测约 100 ms；电机事务超时 20 ms，运动反馈过期 250 ms，上位机保活 300 ms。每 100 ms 心跳或有效速度目标；PING、查询、重复帧和错误帧不续期。保持使能时即使已 STOP 也持续心跳，或明确失能。

首次联调顺序

  1. 单接地址 01 时，把 CAR_SINGLE_MOTOR_TEST 设为 1 后重新编译。双轮默认需要两台都在线。
  2. 发送 PING，再 STATUS，确认 CONFIG=1、ONLINE=1、FAULT=0、初始化完成。
  3. MOTOR ENABLE 1，等 FLAGS bit0=1，再 MOTOR VEL 1 30 10；每 100 ms HEARTBEAT。
  4. STOP 后确认新鲜 RPM=0，再做反转、单次位置、断联及 PB12 急停。
  5. CLEAR_FAULT 异步恢复，故障变 0 且失能后，重新使能并下发新目标；旧目标不会自动恢复。

ARM 编译/链接与软件模拟测试已通过；真实电机运动、TTL 接线、方向和负载仍需上板验收。详细步骤见 下位机实现与联调，完整字段见 上位机协议 v1。
