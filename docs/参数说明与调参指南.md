# SuperCar2 参数说明与调参指南

更新日期：2026-10-05。对应 `car_uart`、`car_motor`、`car_control` 三模块实现。本文写明实际修改入口和验收方法；目前默认参数已通过软件回归，实车参数仍需测量。

## 1. 先分清在哪里调

| 调整内容 | 修改入口 | 生效方式 |
| --- | --- | --- |
| 左右地址、安装方向、速度上限、通信周期、保护开关 | `Core/Inc/car_config.h` | 重新编译、烧录 STM32 |
| 本次速度、加速度档位、位置脉冲、位置模式 | USART2 的 `MOTOR VEL` / `WHEELS` / `MOTOR POS`，或对应二进制命令 | 请求通过门禁后，由电机调度逐台发送 |
| UART 波特率、引脚与时钟 | `SuperCar2.ioc`、CubeMX 和 `Core/Src/main.c` | 重新生成、核对 USER CODE、重新编译烧录；两端设置须匹配 |
| 驱动器地址、Emm 选项、细分、工作电流、驱动器内部闭环参数 | 电机驱动器自身设置 | 按驱动器设置流程完成，再核验配置与运动 |
| 轮径、轮距、减速比、cmd_vel 换算和里程计 | 香橙派上位机 | 实测后填写上位机参数，STM32 继续输出电机轴 RPM / 原始位置反馈 |

STM32 当前没有速度 PID、外部编码器闭环或 PWM 输出。这里的 `acc` 是驱动器协议档位，不是 PID 增益，也不是底盘加速度 m/s²。代码注释集中解释参数单位、状态门禁、停止/恢复、TX 缓冲和调度顺序。

当前电机初始化门禁固定要求 115200、Emm、Receive 和固定 6B。改变电机串口波特率不能只改 `main.c` 的 `BaudRate`，还须同步驱动器设置、`car_motor.c` 的配置匹配条件及相关测试；首次联调保持 115200。

## 2. 常用运动参数

配置头文件已经逐项添加中文注释。默认值如下：

| 配置项 | 默认 | 如何调整 |
| --- | --- | --- |
| `CAR_MOTOR_COUNT` | 2 | 固定双轮结构，保持 2；代码直接访问左右两个槽，不能改成 1 来做单轮测试 |
| `CAR_LEFT_ADDR` / `CAR_RIGHT_ADDR` | 1 / 2 | 当前实际接线为左轮地址 1、右轮地址 2；旧巡线工程曾使用相反映射，不沿用 |
| `CAR_LEFT_SIGN` / `CAR_RIGHT_SIGN` | +1 / -1 | 只取 +1 或 -1；哪一轮的正目标导致倒转，就翻转该轮 sign，再重新烧录 |
| `CAR_MAX_RPM` | 60 RPM | 限制速度绝对值和位置命令速度；超限直接拒绝。先在 10、20、30 RPM 分级验证，再根据负载决定是否提高上限 |
| `CAR_DEFAULT_ACC` | 10 | 仅初始化反馈结构中的档位；运动命令显式传入 acc，会覆盖这个值，调实际起停要改命令参数 |
| `CAR_SINGLE_MOTOR_TEST` | 当前双轮0 | 0=双轮，1=仅左轮地址1，2=仅右轮地址2；电机数量仍保持2；修改后编译烧录，Python分别不加参数/加 `--single`/加 `--single-right` |

方向修正同时用于发送速度/位置和接收反馈。改变 sign 后，上位机仍以“正数=车体前进”发送；不要再把上位机同一轮取反一次。ASCII `STATUS` 中 RPM 也经过修正，应与车体方向一致。

`CAR_MAX_RPM` 是允许目标的上限，不会自动提高当前目标。位置速度要求大于 0。提高上限前，先停止并失能，修改后烧录，以低速重新确认方向再进行负载测试。

`tools/host_link.py` 当前也固定检查 ±60 RPM，地址选项固定 1/2；修改固件上限/地址后，该参考工具不会自动跟随，须同步其参数检查、命令和测试预期。只改 STM32 宏而用旧工具发更高速目标，会被工具提前拒绝。

## 3. 运行时调速、加速度与位置

USART2：115200 / 8N1；每条命令必须以换行结束。先在串口工具里配置 **每 100 ms 自动发送 `HEARTBEAT` 加换行**，使能之后持续运行该定时发送。手工敲字速度不足以稳定满足 300 ms 保活。

### 单轮速度和方向

先将 `CAR_SINGLE_MOTOR_TEST=1`，烧录，单接左地址电机。先发送：

```text
PING
STATUS
```

必须看到左轮地址 1 的 `CONFIG=1`、`ONLINE=1`、`FAULT=0`；然后启用定时心跳，依次发送：

```text
MOTOR ENABLE 1
STATUS
```

等待反馈 `FLAGS` 的 bit0 为 1，再进行正向、停止、反向测试。下面每行是独立步骤，观察反馈和实际动作后再发下一行，不要一次粘贴全部命令：

```text
MOTOR VEL 1 10 10
STOP
MOTOR VEL 1 -10 10
STOP
MOTOR ENABLE 1 0
```

`VEL` 的参数依次是地址、带符号 RPM、加速度档位。确认新鲜反馈 RPM=0 后再换向；最后显式失能，等待实际使能位清零后结束定时心跳。普通 `STOP` 保留使能请求，因此停止期间仍需要心跳。

### 加速度怎么调

保持相同目标速度与负载，例如目标 30 RPM，从 `acc=10` 开始。分别试 `5`、`10`、`20`，每次记录从零到稳定速度所需时间、震动、跟随情况和故障；根据实测选择档位，再测试减速和换向。

```text
MOTOR VEL 1 30 10
```

软件允许 `acc=0..255`，按原值交给 Emm 驱动器。项目协议将 0 定义为直接启动，首次保持 10。不要把档位数字解释成实际 m/s²，或在没有核对驱动器与测量结果时假设“数字越大越快”。`STOP` 使用专门的立即停止帧，测试它不能用来判断正常速度目标下降时的加速度曲线。

### 双轮

改回 `CAR_SINGLE_MOTOR_TEST=0` 并烧录，两台驱动器均在线、配置有效；保持定时心跳，分别请求使能并确认两轮实际使能。然后单独发送：

```text
WHEELS 10 10 10
```

观察应为前进、反馈两轮为正，再 STOP 并确认零速。分别测试 `WHEELS -10 -10 10` 后退和 `WHEELS -10 10 10` 转向；每次动作之间停止并确认反馈。双轮目标先一起检查并接受，随后逐台发送，存在总线传输带来的起动时间差。

结束时 STOP，分别发送 `MOTOR ENABLE 1 0`、`MOTOR ENABLE 2 0`，等待两轮失能，再停止心跳。

### 位置及单位

```text
MOTOR POS 1 3200 30 10 2
```

参数是地址、带符号脉冲数、RPM、acc、模式。位置模式：0=相对上一输入目标，1=相对坐标零点的绝对位置，2=相对当前实时位置。省略模式时默认 2。

位置请求只发一次，随后用心跳保活，并通过状态中的到位位（`FLAGS` bit1）确认完成。不要把 POS 配成串口工具的周期发送项；即使每条请求都有效，重复相对运动也会追加动作。收到 `OK QUEUED` 只表示接受，丢 ACK 后也不能自动重发相对位置。

对实际步距角为 θ 度、细分 M 的电机，控制脉冲数每电机圈为 `(360/θ)*M`。仅在 1.8°、16 细分时，3200 脉冲为一电机圈；有减速器时还需按实际传动比换算到轮子。

二进制位置反馈每电机圈为 **65536 ticks**，与上述控制脉冲单位不同。不要直接拿 3200 去除反馈计数计算圈数。完整位置及采样时刻通过二进制反馈 81 获取，ASCII STATUS 不输出完整 64 位位置。

## 4. 保护和通信周期怎么调

以下宏单位均为毫秒：

| 配置项 | 默认 | 调整影响与判断方法 |
| --- | --- | --- |
| `CAR_HOST_TIMEOUT_MS` | 300 | 无有效保活达到阈值即锁存；先修复心跳周期、重复序号或调度抖动，再决定阈值，增大也会延后断联检测 |
| `CAR_BUS_TIMEOUT_MS` | 20 | 从提交电机 TX 起到收到匹配应答的期限，包含发送与驱动器响应时间；记录完整应答延迟，核对连线和应答设置后才调整 |
| `CAR_MOTOR_FRAME_GAP_MS` | 5 | 两条电机 UART 帧完成后的最小间隔，沿用已验证巡线代码；非阻塞等待，不使用 `HAL_Delay`，过小可能造成共享 TTL/485 接收粘连 |
| `CAR_BUS_QUIET_MS` | 25 | 超时和停止后的安静窗口；过短易受迟到包影响，过长会延后后续查询/恢复 |
| `CAR_RX_FRAME_TIMEOUT_MS` | 20 | 半帧字节间期限，影响电机及上位机二进制解析；ASCII 人工输入不会因慢打字整行过期 |
| `CAR_SPEED_REFRESH_MS` | 50 | 稳定速度重复下发门槛，新目标可优先；降低增加总线压力，不能当作 STM32 PID 周期 |
| `CAR_STATUS_PERIOD_MS` | 50 | 每轮状态与速度的查询门槛；降低增加事务数量，实际周期由两轮排队与应答决定 |
| `CAR_POSITION_PERIOD_MS` | 100 | 位置查询门槛；低于其他查询/运动的优先级，忙时可能延后，应用应看真实采样时刻 |
| `CAR_FEEDBACK_STALE_MS` | 250 | 活动状态下状态/速度过期即故障，恢复也要求新鲜；需覆盖实测最坏查询周期及余量，增大将容忍更旧反馈 |
| `CAR_TELEMETRY_PERIOD_MS` | 100 | 二进制自动回传间隔；只改变主机回报周期，不提高电机采样频率，ASCII 不自动定时回传全部状态 |

调通信周期时，每次只改一项，记录反馈年龄、事务超时及 TX 队列压力；共享总线只有一个普通在途事务，不能把所有周期同时缩短就认为反馈会同步提速。默认值先保持，只有实测证据表明需调整才改。

有效 HEARTBEAT 或已接受的运动/使能请求续期；PING、STATUS、越界请求、CRC 错误以及重复/倒序二进制帧不续期。位置运动结束和零速锁轴期间，只要使能请求仍保留就必须继续保活。

### 开关与容量

| 配置项 | 默认 | 使用说明 |
| --- | --- | --- |
| `CAR_USE_ESTOP_PIN` | 1 | PB12 上拉、低有效；接 GND 触发，释放后才允许恢复，常规保持启用 |
| `CAR_USE_FAULT_PINS` | 0 | 有经过确认的独立低有效报警输出才开启 PB13/14；不能复用 UART 回包引脚作为报警线 |
| `CAR_USE_IWDG` | 1 | 启用主循环看门狗；不是时长参数，常规保持启用 |
| `CAR_RX_RING_SIZE` | 256 字节/路 | 默认每路最多存 255 字节，一格保留区分空/满；增大占 RAM，溢出时先排查主循环是否被阻塞 |
| `CAR_HOST_TX_DEPTH` | 8 槽 | 部分槽须保留给空/满判别和 HAL 在途帧，不能当作可再排 8 帧；增大不能增加 UART 带宽 |
| `CAR_HOST_MAX_PAYLOAD` | 64 字节 | v1 协议限制，常规不改；修改需同步上位机、编码长度及所有相关测试 |

### 当前固定在源码中的值

| 位置 | 当前值 | 注意事项 |
| --- | --- | --- |
| `car_uart.c` → `CarUart_Poll` | TX 超过 20 ms 卡住则终止并报 UART 故障 | 与 `CAR_BUS_TIMEOUT_MS` 独立；只加大应答超时不会改变这里 |
| `car_uart.c` → `CarUart_SendMotor` | `CAR_MOTOR_FRAME_GAP_MS` 默认 5 ms | 对齐旧巡线代码两帧之间的实测间隔；函数立即返回，主循环稍后重试 |
| `car_motor.c` → `CarMotor_StopAll` | FE 98 停止后补发 F6 零速帧 | 保留当前优先停止机制，同时兼容旧代码实际使用的 `addr F6 00 00 00 00 6B` 停止方式 |
| `car_control.c` → `board_init` | IWDG PR=4（64 分频）、RLR=624 | 超时约 `64*(624+1)/f_LSI` 秒，标称约 1 s；实际时序上板测量，改寄存器还需同步板级测试 |
| `car_control.c` → `board_poll` | 正常 LED 500 ms、故障 100 ms 翻转 | 是翻转间隔，完整亮灭周期分别为 1 s、200 ms |
| `car_motor.c` → `CarMotor_Poll` | 故障下未停/反馈过期约每 100 ms 重发停止 | 不能拿它当普通速度刷新周期 |
| `car_motor.c` → `transaction_failed` / 配置失败 | 初始化核验延后 500 ms 重试 | 故障仍锁存，不会自动恢复运动 |

这些是诊断和实现说明，常规联调先保持原值。禁止靠关闭急停/看门狗、绕过配置门禁或强行清故障来获得运动。

## 5. 用反馈定位问题

| 表现 | 先检查什么 |
| --- | --- |
| `ERR ARGUMENT` | RPM 是否越限、位置速度是否为 0、acc 是否 0..255、地址/模式/字段是否有效 |
| `ERR NOT_READY` | CONFIG、ONLINE、初始化是否完成，实际使能位与请求是否一致 |
| `ERR SAFETY_LOCK` | FAULT 位掩码，物理输入是否释放，是否完成异步恢复 |
| `ERR BUSY` | STOPPING 是否已确认零速，前一位置是否还在等待 ACK |
| FAULT 含 2 | 心跳周期、二进制序号是否重复，STOP 后是否误停了心跳 |
| FAULT 含 4 | 电机地址/波特率/接线/应答设置、事务响应时间、状态与速度反馈年龄 |
| FAULT 含 8 | 驱动器堵转/保护标志、实际负载和驱动器自身设置 |
| FAULT 含 16 | 驱动器是否为 Emm、UART/115200/Receive/6B、地址和输入缩小选项 |
| FAULT 含 32 | RX 错误/溢出、TX 卡死、主循环是否阻塞、串口发送负载 |

FAULT 是位掩码，可同时包含多项。ASCII `AGE` 是速度反馈年龄；二进制 81 分别带速度和位置的采样时间。不要只看目标 RPM 或 `OK QUEUED` 判断运动正常。

恢复时先排除故障源、释放输入，然后发送 `CLEAR_FAULT`。`OK RECOVERY` 只表示接受；继续查询，等 `FAULT=0` 且电机已失能，才重新使能和下发新目标，不重放故障前动作。

## 6. 修改后怎么验证和记录

修改编译期配置后，编译并烧录实际固件：

```powershell
python tools/build_firmware.py --toolchain E:/Keil5/Core/ARM/ARMCC/bin
```

命令行 HEX 位于 `build/firmware/SuperCar2.hex`。如果在 Keil 中下载，先重新编译该 Keil 工程；命令行编译不会更新 Keil 自身输出目录，不要误烧录旧文件。

默认双轮配置的软件回归命令：

```powershell
python tools/test_firmware.py --cc C:/mingw64/bin/gcc.exe
python tools/sync_embedded_docs.py --check
```

当前模拟回归固定按默认双轮、地址 1/2、60 RPM 上限及默认保护阈值验收。若有意改为单轮、其他地址/上限/阈值，要同步相应模拟器和断言；不要通过删除测试来消除预期差异。

`tools/host_link.py` 不带 `--port` 时只生成协议帧，适合检查字段，不会操作电机：

```powershell
python tools/host_link.py --type velocity --left 10 --right 10 --acc 10 --seq 1
```

参考工具的 `--type run` 适用于默认地址双轮，依赖 Python pyserial，可在人工核验方向/接线并具备停止条件后，指定实际 COM 口运行短时低速测试。它会使能双轮、周期发目标、结束发 STOP；结束后没有自动失能，心跳中断仍可能触发主机超时。不要把它当作首次单轮方向测试工具。

每次只改一项，建议记录：配置版本、单/双轮、地址/sign、目标 RPM/acc、负载、反馈 RPM/AGE、到速时间、异常/故障掩码与恢复结果。按单轮方向→低速起停→双轮前后/转向→位置单次到位→负载→断联/急停/看门狗逐步验证。实测轮径、轮距和传动比记录到香橙派配置。
