# 笔记本作为 STM32 上位机的串口测试

新增程序：工程根目录 `stm32_host_test.py`。日期：2026-10-09。

当前使用双轮地址1/2：固件 `CAR_SINGLE_MOTOR_TEST` 配置为0，**重新编译并烧录STM32后**运行：

```powershell
python stm32_host_test.py --port COM11 status
python stm32_host_test.py --port COM11 wheels 10 10 --run 2
python stm32_host_test.py --port COM11 wheels -10 -10 --run 2
```

COM11替换成实际端口。以下双轮例子使用当前模式0；左轮单接使用模式1，右轮单接使用模式2，每次切换都要重新编译烧录。香橙派可使用根目录 `orangepi_host_test.py`，默认 `/dev/ttyS0`，命令参数相同。

## 1. 两个测试程序分别接哪里

你已经测通的 `test.py` 发送 `01 F6 ... 6B` 等 Emm 帧，连接的是电机驱动器。
新程序发送 STM32 上位机 ASCII 指令，连接的是 STM32 的 USART2。

```text
笔记本 Python -> USB-TTL（例如 CH343）-> STM32 USART2
                                      STM32 USART1 -> 左/右 Emm 驱动器 -> 步进电机
```

笔记本此时承担香橙派的上位机通信角色。ASCII 和二进制都是当前固件支持的上位机接口；这份测试程序选择可直接阅读的 ASCII，后续 ROS 可使用已有 `tools/host_link.py` 的二进制协议。不要在同一串口会话混发两种协议。

## 2. 接线

| USB-TTL 端 | STM32 端 | 说明 |
| --- | --- | --- |
| TXD | PA3 / USART2_RX | 电脑发送，STM32接收 |
| RXD | PA2 / USART2_TX | STM32回复，电脑接收 |
| GND | GND | 共地；驱动器通信地按原接线保持共地 |

- 使用 **3.3 V TTL 信号电平**，确认模块跳线改变的是信号电平还是只改变 VCC 输出。不要把 RS232/RS485 接口直接接到 STM32 TTL 引脚。STM32F103 的供电范围和各引脚电气条件见 [ST 数据手册](https://www.st.com/resource/en/datasheet/stm32f103rb.pdf)。
- STM32 已由 USB 或其他电源供电时，USB-TTL 的 VCC 通常不接；避免多个电源输出互相连接。电机由驱动器动力电源供电，不能由 USB-TTL 供电。
- STM32 到驱动器继续使用现有 PA9 / USART1_TX、PA10 / USART1_RX 接线。电脑这次接 **PA2/PA3**，不能继续用原来的驱动器直连位置发送上位机命令。
- 暂时断开香橙派的 UART 连接，同一个 STM32 RX 不接两个上位机 TX。
- ST-Link 的下载接口不等于本测试的 USART2；开发板的 USB 插口也不自动等于 USART2。设备管理器里应选择 USB-TTL 的 COM 号。

## 4. 先确认通信与状态

```powershell
python stm32_host_test.py --port COM11 ping
python stm32_host_test.py --port COM11 status
```

PING 应显示 `[RX] OK PONG`。它只证明电脑与 STM32 通信成功，不能证明驱动器通信成功。

状态例子（双轮会依次查询地址1/2，下面展示右轮；实际数值以板子反馈为准）：

```text
[TX] MOTOR STATUS 2
[RX] DATA MOTOR 2 STATE 1 RPM 0 FLAGS 0 FAULT 0
[RX] DATA FEEDBACK 2 ONLINE 1 CONFIG 1 AGE 25
```

- `ONLINE=1`：驱动器在线。
- `CONFIG=1`：驱动器参数通过固件检查。
- `FAULT=0`：没有锁存故障。
- `AGE`：速度反馈距当前 STM32 时间的毫秒数，测试要求小于250。
- `STATE=1`：失能；`STATE=2`：已使能且就绪；3速度、4位置、5停止中、6故障。
- `FLAGS` 是位掩码，bit0表示使能、bit1表示位置到达、bit2/3表示堵转/保护。

`status` 和 `ping` 不使能、不运动，也不续期心跳。不要用另开一个 status 程序接管仍在运动的会话。

## 5. 双轮固件：先分别测试，再双轮

本节使用当前 `CAR_SINGLE_MOTOR_TEST=0`，须先重新烧录，**两个地址1/2的驱动器都要上电并正确回包**。`left` / `right` 表示只让选定轮运动，另一轮保持失能；它们不绕过另一驱动器的初始化/故障检查。

先架空车轮/固定电机，以20 RPM测试方向：

```powershell
# 左轮前进3秒；正常结束自动停止并失能两轮
python stm32_host_test.py --port COM11 left 20 --run 3

# 左轮后退3秒
python stm32_host_test.py --port COM11 left -20 --run 3

# 右轮前进3秒
python stm32_host_test.py --port COM11 right 20 --run 3

# 右轮后退3秒
python stm32_host_test.py --port COM11 right -20 --run 3

# 两轮前进3秒
python stm32_host_test.py --port COM11 wheels 20 20 --acc 10 --run 3

# 两轮后退3秒
python stm32_host_test.py --port COM11 wheels -20 -20 --run 3

# 左轮后退、右轮前进，低速转向测试
python stm32_host_test.py --port COM11 wheels -15 15 --run 2
```

**RPM正数表示车体前进方向**；右电机的物理方向翻转由 STM32 的 `CAR_RIGHT_SIGN=-1` 完成，Python不要再翻转一次。装车镜像关系需实测；若某侧方向错误，修改固件 sign 并重新烧录。

程序流程：PING → STOP并等零速/在线/配置有效 → 失能并确认 → 使能所选电机并确认READY → 发一次运动目标 → 每100 ms心跳、循环查询状态 → STOP → 失能 → 确认零速/失能 → 关闭串口。

`OK QUEUED` 只说明 STM32 接受请求，程序随后仍会等待状态确认。默认加速度10；速度默认限制为当前固件的±60 RPM，加速度为0..255档位，0为直接启动，不建议首次使用。若修改固件地址/限速/反馈阈值，须同步修改本程序顶部常量。

## 6. 真正只接一台电机：左右都支持

固件模式与Python参数必须对应：

| 接线 | CAR_SINGLE_MOTOR_TEST | Python全局参数 |
| --- | --- | --- |
| 两轮地址1/2（当前配置） | 0 | 不加单轮参数 |
| 仅左轮地址1 | 1 | `--single` |
| 仅右轮地址2 | 2 | `--single-right` |

仅右轮时保持驱动器地址2，不修改左右地址或sign。先改为模式2并重新编译烧录后运行：

```powershell
python stm32_host_test.py --port COM11 --single-right ping
python stm32_host_test.py --port COM11 --single-right status
python stm32_host_test.py --port COM11 --single-right right 20 --run 3
python stm32_host_test.py --port COM11 --single-right right -20 --run 3
python stm32_host_test.py --port COM11 --single-right position right 800 --rpm 20 --run 10
python stm32_host_test.py --port COM11 --single-right stop
python stm32_host_test.py --port COM11 --single-right recover
```

仅左轮的步骤：

1. 使用地址 **1** 的左轮驱动器。
2. 修改 `Core/Inc/car_config.h`：`CAR_SINGLE_MOTOR_TEST` 设为 `1`，重新编译并下载。
3. 每次运行加上全局参数 `--single`：

```powershell
python stm32_host_test.py --port COM11 --single status
python stm32_host_test.py --port COM11 --single left 20 --run 3
python stm32_host_test.py --port COM11 --single left -20 --run 3
python stm32_host_test.py --port COM11 --single stop
python stm32_host_test.py --port COM11 --single recover
```

**`--single` / `--single-right` 不会更改固件。** 软件参数与烧录模式必须一致。恢复双轮时宏改回0，重新烧录，并去掉单轮参数。

## 7. 位置测试

```powershell
# 左轮相对当前位置前进800细分脉冲，20 RPM；观察上限10秒
python stm32_host_test.py --port COM11 position left 800 --rpm 20 --acc 10 --run 10

# 右轮相对当前位置后退800细分脉冲
python stm32_host_test.py --port COM11 position right -800 --rpm 20 --run 10
```

默认 `--mode 2` 表示相对当前位置；0相对上一输入目标，1相对驱动器坐标零点的绝对位置。脉冲数并非角度、毫米或反馈ticks；只有1.8°电机且16细分时3200脉冲才是电机轴一圈，此时800脉冲是四分之一圈，机械减速比另算。

位置指令只发一次，随后靠心跳保持通信。新鲜状态为READY、到位位为1、RPM为0时提前结束；超过 `--run` 未确认到位则停止并返回失败。收到 ACK 超时不会自动重发位置指令，先核对实际位置再决定下一次操作。

## 8. 停止、急停与恢复

```powershell
# 正常停止并失能；本命令退出后不再发心跳
python stm32_host_test.py --port COM11 stop

# 软件急停：停止并锁存急停故障
python stm32_host_test.py --port COM11 estop

# 修正故障原因、释放PB12后，显式恢复；不重新使能/运动
python stm32_host_test.py --port COM11 recover
```

运行中的测试用 **Ctrl+C** 中断，程序在退出流程中继续心跳，发送STOP、失能并等待确认。运行程序占着COM时，另一个 stop 程序无法同时打开该COM；紧急情况使用硬件急停。

- 当前固件STOP会停止**双轮**，并保持原有使能。测试程序为避免退出后心跳超时，随后明确失能并确认；**失能后不保持锁轴力矩**，斜坡或有悬挂负载的机构要先机械固定。
- 上位机有效保活断开约300 ms后，STM32锁存心跳超时；PING/STATUS不保活。Windows/Python不是实时系统，休眠、暂停调试、USB断开或严重调度延迟都可能触发故障，不要为规避这些现象关保护。
- 强制结束进程、笔记本断电、USB线拔掉时Python的退出处理可能无法执行，STM32保护会尽力发送停止；STM32到驱动器的通信也断开时不能保证软件停止，保留硬件急停/断电手段。
- PB12低电平触发急停，恢复前应释放。不要为了恢复自动短接/禁用急停保护。
- 程序不会自动清故障。`OK RECOVERY` 只是恢复流程已接受，必须等待故障0、在线/配置有效、零速和失能；恢复失败需排除原因后再执行。

## 9. 常见错误

| 现象 | 优先检查 |
| --- | --- |
| 无 `OK PONG` / 应答超时 | COM号、TX/RX交叉、GND、115200、接PA2/PA3、当前程序是否已下载 |
| Access denied / 无法打开COM | 关闭串口助手和占用端口的其他程序；检查驱动 |
| `ERR NOT_READY` | 电机是否上电、初始化/使能是否完成、两台驱动器是否都在线 |
| `ERR SAFETY_LOCK` | 先status看故障码，修正后recover，不能仅重发速度 |
| `ERR BUSY` | 停止/位置事务尚未完成，先看状态，不重复发位置目标 |
| FAULT含2 | 心跳超时；USB、休眠、程序暂停、系统卡顿 |
| FAULT含4 | 电机串口回包/事务超时；检查PA9/PA10、供电、地址、共享总线 |
| FAULT含16 / CONFIG=0 | 驱动器UART、115200、地址1/2、固定6B、Response=Receive、Emm固件/选项、关闭输入缩小 |
| 退出提示“停止/失能未全部确认” | 不等于已成功停止；检查实际运动与供电，必要时硬件急停 |

故障值是位掩码，例如6=2+4，可能同时存在多个原因。程序会打印对应中文说明。
原 `test.py` 能转动只验证了直连速度指令；STM32还要求驱动器查询回包、配置门禁和实时状态都正常。

### 配置已通过但FAULT=68：在STM32链路上记录出错应答

ONLINE=1、CONFIG=1、AGE较小表示已有有效配置和新鲜速度反馈；FAULT=68为4+64，包含历史通信超时和指令拒绝/非法反馈，单凭STATUS不能确定是哪条指令。新增的 `diag` 可直接通过USB-TTL→STM32现有连接查询，**需Rebuild并下载含诊断功能的新固件**，不需要切换到驱动器直连。

```powershell
python stm32_host_test.py --port COM11 --single-right diag
```

程序先查STATUS，再发送 `MOTOR DIAG 2`，显示DATA DIAG/TIMEOUT/REJECT三行。TIMEOUT/REJECT给出功能码和原始回包（最多前8字节），可区分哪个查询无回复、哪些ACK/字段被固件拒绝。记录复位时清空，如果重新烧录后故障没有复现，功能码可能为0。该命令不使能、不运动、不清故障、不发送心跳；保存诊断结果后再决定是否recover。原有保护门禁不改变。

### ONLINE短暂为1、CONFIG一直为0时，读取原始回包

`recover` 返回 `OK RECOVERY` 只表示请求已接收，不表示已恢复。`ONLINE` 短暂为1说明至少一个匹配事务收到有效回包，随后又为0说明其他事务仍失败，不能仅凭日志确定是接线、延迟还是回包格式。

工程根目录 `motor_uart_diag.py` 提供只读驱动器直连诊断。它发 `1A`选项、`42`配置、`3A`状态、`35`速度查询，打印全部原始字节。不会发运动/使能/清保护/参数写入，也不会停止之前已存在的运动。

1. 结束上位机程序，确认电机已静止并机械固定，接线前按实际供电条件断电。
2. 暂时断开STM32 PA9/PA10与驱动器的连接，避免STM32继续向同一驱动器发送查询。
3. 把USB-TTL从STM32 PA2/PA3移到驱动器：USB-TTL TX→驱动器RX，RX←驱动器TX，GND共地；确认驱动器动力电源已恢复。
4. 运行下列命令（COM号换成当前USB-TTL端口）：

```powershell
python motor_uart_diag.py --port COM11 --direct-driver --addr 2
```

**该命令不能在USB-TTL仍接STM32 USART2时使用。** `--direct-driver` 表示当前已改为直连驱动器；请贴出四组TX/RX，尤其1A和42。

当前STM32解析器只接受42配置回包33字节、第三字节0x21。若直连收到其他长度或错误应答，应根据实际版本/协议核对固件解析；不能直接关闭配置门禁。直连有回复而经STM32失败时再检查PA9→驱动器RX、PA10←驱动器TX及回包时序。

2026-10-09已定位并修正的实例：用户X42S_V1.0/Emm实测1A返回 `02 1A 00 06 6B`（5字节），42配置返回33字节且检查字段全部符合要求。原固件/诊断程序把1A当4字节，导致有效回包被丢弃；已修正为5字节、大端16位选项 `0x0006`，模拟测试也采用实测回包。遇到这组输出时，不需要更改驱动器地址/波特率或关闭保护，应重新编译下载修正后的STM32固件。

更新固件后恢复正常链路：USB-TTL TX→PA3、RX←PA2；STM32 PA9→驱动器RX、PA10←驱动器TX、共地。运行 `python stm32_host_test.py --port COM11 --single-right status`，确认ONLINE=1、CONFIG=1、FAULT=0后，再做低速运动测试。

诊断结束按原接线恢复USB-TTL到PA2/PA3、STM32到驱动器。此诊断程序本身不需要重新烧录STM32。
