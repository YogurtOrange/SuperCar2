## 3. 硬件与默认配置

STM32F103C8T6，HAL F1，HSE 8 MHz、PLL×9、SYSCLK 72 MHz。使用 Keil ARM Compiler 5；64 KB Flash / 20 KB RAM。

| 引脚 | 当前用途 |
| --- | --- |
| PA9 / PA10 | USART1 TX / RX：共享 TTL 电机总线，115200 / 8N1，左地址 1、右地址 2 |
| PA2 / PA3 | USART2 TX / RX：香橙派/替代调试串口，115200 / 8N1 |
| PB12 | 上拉输入，低有效急停，默认启用 |
| PB13 / PB14 | 上拉输入，可选左右报警；默认不参与保护 |
| PC13 | 低有效 LED；健康 500 ms、故障 100 ms 翻转 |
| PA13 / PA14 | 保留 SWD |

香橙派 UART1 物理 5 脚 TX→STM32 PA3，物理 3 脚 RX←PA2，公共地。CH343 是替代入口。共享电机接线针对厂商支持多机总线的 TTL 驱动版本；当前没有 RS485 DE/RE、CAN、PWM、外部编码器或 DMA 控制。

当前实际左右地址为 1/2，方向默认 +1/-1，限速 ±60 RPM，加速度 10；旧巡线工程曾使用相反地址映射，不沿用。实际安装方向待低速实测。单轮开关默认为 0；改为 1 时仅联调左轮。IWDG 默认启用，标称约 1 s，调试暂停时冻结，由主循环喂狗。GPIO 在 `.ioc` 和当前 `car_control.c` 都有初始化。

关键周期：主机保活 300 ms，电机事务 20 ms，超时后总线安静 25 ms，电机帧间隔 5 ms，接收半帧超时 20 ms；速度刷新及状态/速度查询约 50 ms，位置查询约 100 ms，反馈过期 250 ms，遥测 100 ms。RX 环形队列 256 字节，主机 TX 队列 8 槽，主机最大 payload 64 字节。最终数值以配置头文件为准。

## 4. 已保留的关键行为（后续修改继续遵守）

### 4.1 初始化与驱动配置

上电先发停止，逐台查询选项 `1A`、配置 `42`、状态 `3A`、速度 `35`，然后失能；不自动使能或运动。

当前状态机只支持 Emm。要求 UART、115200、正确地址、固定 `6B` 校验、Response=Receive、Emm 选项有效、关闭输入缩小 10 倍。`42` Emm 配置回包要求 33 字节/21 参数。参数不符合时锁存故障，不自动写入永久驱动设置。配置回包的非法长度应拒绝，丢弃后仍能解析后续合法 Emm 回包。

使能必须已完成初始化、配置有效且在线；运动还需已请求并确认使能。双轮请求先验证两轮，再接受，硬件发送仍逐台执行，不改成同步广播。

### 4.2 串口和共享总线

HAL UART 回调已统一在 `car_uart.c`，整个工程只能各定义一次。ISR 搬字节、维护传输及接收重挂；协议和运动状态机在主循环运行。

TX 使用持久缓冲，直到发送完成不得覆盖；电机发送缓冲和主机队列均有此约束。TX 卡住超过 20 ms 会终止发送并锁存故障。RX 错误、溢出与恢复机制须保留；队列满不能阻塞控制或覆盖正在发送的内容。

正常电机总线只允许一个在途事务，按地址和功能码匹配。回包按已知长度/配置长度解析，payload 中出现 `6B` 不能提前截帧。

### 4.3 调度顺序

当前初始化顺序：板级 IO → 串口 → 安全 → 上位机协议 → 电机管理 → 遥测计时。

当前 `CarControl_Poll` 每轮调度顺序：

```text
读取 HAL_GetTick
维护 UART、发送和串口错误
检查物理输入/保活保护
解析并处理上位机命令
再次检查保护（命令可能刚改变活动状态）
运行电机状态机和事务
按周期发送遥测
更新 LED、喂 IWDG
```

先检查物理急停，再接受命令；处理同一批命令时 ESTOP 必须清除待执行目标。合并文件不能引入运行期 `HAL_Delay`、阻塞发送、等待驱动 ACK 的死循环或动态内存。

### 4.4 停止、保活和恢复

- 普通 STOP 清目标并停止双轮，保留使能请求。处于已使能零速/停止状态时仍需保活；`PING` 不保活。
- 所有故障锁存并停止双轮。新速度/心跳不能自动清故障。已接受的有效保活/运动命令才按当前规则刷新时间。
- 急停/故障停止取消正常事务等待、清掉运动目标和旧解析状态；已开始的 UART 帧先发完，然后发送两个 `FE 98`，不等待左轮停止 ACK 才停右轮。停止 ACK 不按正常事务处理；查询速度确认停止，异常时约每 100 ms 重发停止。
- CLEAR_FAULT 是异步恢复：输入释放→停止→`0E 52` 解除保护→失能→检查在线/配置/新鲜状态和速度/零速/无保护/已失能→清锁存。恢复后仍失能，必须重新使能和给目标，不重放故障前命令。
- 位置命令只发一次。ACK 丢失后故障停机，不自动重发位置；完成依据后续 `3A` 到位标志。现有位置模式 0/1/2 和默认模式 2 保留。
- 停止兼容旧巡线实测：优先发送 `FE 98` 专用停止帧，随后补发 `F6` 零速、acc=0、snF=0 帧；两种停止帧均不等待 ACK，之后再用反馈确认零速。

### 4.5 协议兼容与反馈

以 `docs/上位机协议_v1.md` 为准：头 `AA 55`，版本 1，最大 payload 64；CRC16-Modbus 初值 FFFF、多项式 A001，覆盖版本到 payload，CRC 低字节先发。`123456789` 校验为 `4B37`。

TYPE：01 双轮速度、02 双轮位置、03 STOP、04 ESTOP、05 使能、06 清故障、10 心跳、11 查询、12 HELLO；80 状态、81 反馈、82 故障、83 ACK。保留长度和参数校验、序号向前 1..127 的模 256 规则、重复/乱序拒绝；STOP/ESTOP/HELLO 的序号例外及 HELLO 停止/失能/重置序号但保留故障的行为不变。

`OK QUEUED` / ACK 成功是接受请求，不等于电机已执行；恢复请求也不是已经恢复。反馈保持有符号 RPM、有符号 64 位位置计数和各自采样时间；Emm 位置计数每转 65536，与发送位置命令的微步脉冲数不是同一单位。保留方向修正，不在 STM32 填虚构轮径/轮距。

故障位依次为 ESTOP=1、主机超时=2、电机通信=4、驱动保护=8、配置=16、UART=32、命令=64。电机状态编号为 INIT=0、DISABLED=1、READY=2、SPEED=3、POSITION=4、STOPPING=5、FAULT=6。
