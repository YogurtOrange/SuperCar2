# ROS 小车未知环境自主探索方案（当前实施版）

更新日期：2026-10-05。硬件目标为香橙派 5、STM32F103C8T6、左右 X42S/Emm 驱动器、Livox Mid-360，CH343 用于备用调试。下位机工程为 SuperCar2；STM32 软件已实现、编译和模拟测试通过，实车与 ROS 部分尚待实施。

## 1. 系统边界与实际链路

香橙派负责雷达驱动、定位建图、地图处理、探索规划、Nav2、cmd_vel 转换、里程计与 TF。STM32 负责执行左右轮 RPM/脉冲位置、驱动器串口事务、保护、状态和真实位置回传。

```text
Mid-360 ── Ethernet ── 香橙派
                       ├── 点云预处理 /scan / 地图
                       ├── SLAM / 定位 / TF
                       ├── Nav2 ← frontier_explorer
                       └── base_driver：cmd_vel ↔ 下位机反馈
                                  │ UART1（物理 5 TX / 3 RX）
                                  ▼
                          STM32 USART2（PA2 / PA3）
                           SuperCar2 控制与保护
                                  │ USART1（PA9 / PA10）
                                  ├── 左 X42S / Emm 地址 01
                                  └── 右 X42S / Emm 地址 02
```

CH343 可替代香橙派直连 STM32 USART2；不会改变下位机协议。USART3、I2C、PWM、外部编码器目前未启用。电机共享 TTL 接法限于厂商支持多机的硬件版本；电机为 RS485/CAN 时需要适配。

## 2. 当前下位机基线

| 内容 | 实际实现 |
| --- | --- |
| 接口 | USART2 上位机，USART1 双轮总线，均 115200 / 8N1 |
| 控制 | 单轮/双轮整数 RPM，单轮/双轮脉冲位置，明确使能、停止、急停、恢复 |
| 驱动器 | Emm 固件，地址 01/02，6B 校验，Response=Receive，无输入缩放 |
| 启动 | 停止→读取选项/配置/状态/速度→失能，确认后才允许使能和运动 |
| 调度 | 非阻塞 TX，中断 RX，一次等待一个电机应答，逐轮执行 |
| 周期 | 速度/状态约 50 ms；位置/遥测约 100 ms |
| 保护 | 上位机 300 ms 保活、20 ms 电机事务超时、250 ms 反馈过期、UART 错误、PB12 急停、驱动器保护 |
| 看门狗 | 独立看门狗标称约 1 s，主循环喂狗 |
| 初始限制 | ±60 RPM，加速度档位 10，左 +1 / 右 -1，方向须标定 |
| 回传 | 状态、故障、真实 RPM、int64 位置 ticks 与各自采样时间 |

PB12 是输入上拉低有效急停，默认启用。PB13/14 是可选报警输入，已配置上拉但默认不参与保护；PC13 输出状态 LED。当前轮径/轮距/减速比没有填入假值。

初版接受毫秒级逐轮起动差，不使用广播同步。当前实际接线左地址 1、右地址 2，电机协议只使用 Emm 固件，速度单位为电机轴 RPM。

## 3. ROS base_driver 通信契约

正式帧为 `AA 55 01 TYPE LEN SEQ PAYLOAD CRC_LO CRC_HI`。CRC16/MODBUS 覆盖 VER 至 PAYLOAD，payload 小端，最大 64 字节。完整契约见 [上位机协议 v1](上位机协议_v1.md)，不得另定义重复消息编号。

| 消息 | 类型 |
| --- | --- |
| 左右轮 RPM / 位置脉冲 | 01 / 02 |
| 停止 / 急停 / 单轮使能 / 恢复 | 03 / 04 / 05 / 06 |
| 心跳 / 查询 / HELLO | 10 / 11 / 12 |
| 状态 / 速度位置反馈 / 故障变化 / 接受应答 | 80 / 81 / 82 / 83 |

上位机连接后 HELLO 停止并失能，重设接收序号；等待配置、在线、故障为零，再逐轮使能，等真实使能状态确认后才运动。新请求序号递增，重复/倒序帧不执行、不续期；位置只发送一次，ACK 丢失用查询确认，不能重发相对位置。

base_driver 每 100 ms 发送有效速度目标或心跳。驱动使能后即使零速/STOP 也维持心跳，退出时 STOP，并按需要明确失能。发现 faults 非零、离线或反馈过期，先停止导航输出，取消当前 Nav2 任务并进入人工/受控恢复流程；不能自动 CLEAR_FAULT 然后恢复旧 cmd_vel。

CLEAR_FAULT 是异步恢复，故障解除并确认失能后还要重新使能。硬件急停未释放、驱动器未在线或仍有保护时不能解除锁存。

## 4. 底盘运动与里程计

先实测滚动轮径 D、轮距 B、减速比 G（电机圈/车轮圈）、细分与左右方向。两轮差速换算在香橙派进行：

```text
v_left  = v_x - w_z * B / 2
v_right = v_x + w_z * B / 2
motor_rpm = wheel_linear_speed / (pi * D) * 60 * G
```

根据 STM32 实际限速约束 cmd_vel，避免把超限拒绝当作正常运动。两侧速度需要共同缩放时由上位机处理，以维持转弯曲率。

反馈 81 的 position_ticks 为方向映射后的真实 Emm 位置，65536 ticks/电机圈。位置控制脉冲数是另一种单位：1.8°、16 细分默认 3200 脉冲/圈。里程计按反馈差计算：

```text
distance_left/right = delta_ticks / (65536 * G) * pi * D
delta_s = (distance_left + distance_right) / 2
delta_yaw = (distance_right - distance_left) / B
```

每轮反馈含速度和位置采样时刻，两轮不是严格同时采样。初次反馈只建立基线；检测重启、回绕、故障复位或时间戳不连续时重建基线，不能把新绝对位置直接累计进旧 odom。检查时间戳与 online/config_ok，避免旧值生成实时 odom。

计划发布 /odom、/joint_states、底盘状态和 odom→base_link。驱动器反馈可反映电机实际位置，但车轮打滑仍会形成位姿误差；后续与激光里程计融合，需要时再增加 IMU。

## 5. 雷达、定位与地图路线

保留原方案的分阶段路线，先验证每条数据链路，再整合导航。ROS 发行版、香橙派系统镜像和驱动版本须根据实际安装环境冻结，目前不假定已经部署。

第一阶段计划：

1. Mid-360 通过以太网接入香橙派，确认实际 IP、点云频率、坐标系和时钟。
2. 定义 base_link→lidar 静态 TF，按雷达实际安装高度和车体外廓裁剪点云。
3. 降采样并过滤车体自点云，保留适合 2D 障碍地图的高度范围。
4. 点云投影成 /scan，接入 pointcloud_to_laserscan 与 slam_toolbox，验证 2D 建图。
5. 检查 /map、/odom、TF 与实际前后转向一致。

后续增强路线为激光惯导定位（FAST-LIO2/Point-LIO 类方案），将点云投影/栅格化供 Nav2 使用。升级前先用实测场景判断 2D 投影是否满足门槛、低矮障碍、玻璃等要求，避免同时更换底盘接口和定位体系。

## 6. Nav2 和自主探索

先在已知地图验证单目标导航，按实际车体配置 footprint、障碍层、膨胀半径、速度和加速度。允许速度受当前固件 ±60 RPM 和实测负载能力共同限制。

frontier_explorer 的计划流程：

1. 从 /map 找自由栅格与未知栅格相邻的 frontier。
2. 聚类并过滤过小、不可达、进入障碍膨胀区的簇。
3. 按距离、信息增益、方向变化、访问次数和失败记录评分。
4. 选择安全目标，通过 NavigateToPose 请求 Nav2。
5. 不可达或重复失败时标记并换目标，连续无可达 frontier 时进入完成状态。

探索节点调用 Nav2，不直接发电机命令。手动/自动控制都经过统一 base_driver。急停和下位机故障优先于探索状态，故障恢复需要明确的新任务。

## 7. 包结构规划

| ROS 包 | 计划职责 |
| --- | --- |
| robot_bringup | 启动、驱动/导航/融合配置 |
| stm32_base_driver | 串口、cmd_vel 换算、保活、状态、反馈、odom |
| robot_description | URDF、车体尺寸、轮子及雷达静态 TF |
| lidar_preprocess | 点云裁剪、降采样、车体过滤、投影 |
| frontier_explorer | 前沿聚类、评分、Nav2 目标和失败处理 |

这些 ROS 包尚未在当前 STM32 工程中实现。电机底层已位于 SuperCar2 的 car_motor.c，无需另把它当作香橙派 ROS 电机驱动包。Python `tools/host_link.py` 是通信参考及桌面联调工具，不是完整 ROS 节点。
